# 需求规格说明书 - Agent工作助手

**版本**: 1.0
**更新日期**: 2026-08-03
**状态**: 草案

## 1. 项目概述

### 1.1 产品定位

Agent工作助手是一款纯本地 Android 应用，通过对接第三方 AI 模型 API 实现智能创作辅助功能。产品定位：

- **目标用户**: 小说作家、编剧、分镜师、内容创作者
- **核心价值**: 降低创作门槛，提升创作效率，实现创作流程自动化
- **差异化**: 纯本地运行，无需自建后端；技能可扩展，记忆可持久化

### 1.2 参考项目

| 项目 | 地址 | 参考内容 |
|------|------|----------|
| OmniBot | https://github.com/omnimind-ai/OpenOmniBot | 端侧 AI Agent 架构、技能体系、工作区管理、记忆系统、状态机驱动 |
| Zorv AI | https://github.com/Quor-a/ZorvAI | ACI 跨应用调用、多模型对话、人格系统、流式响应 |
| ArcReel | https://github.com/ArcReel/ArcReel | 多供应商抽象层、角色一致性、费用追踪、版本管理 |

### 1.3 术语表

| 术语 | 定义 |
|------|------|
| 模型供应商 | 提供 LLM API 的服务商（如 DeepSeek、OpenAI、Claude、Gemini 等） |
| API Key | 用户在应用中配置的模型供应商认证密钥 |
| 工作区 (Workspace) | Agent 的持久化存储目录，包含记忆文件、模型、附件等 |
| 技能 (Skill) | 可安装的扩展模块，为 Agent 提供特定能力 |
| 记忆系统 | 三层记忆：SOUL.md（角色）、CHAT.md（提示）、MEMORY.md（长期记忆） |
| 分镜 | 剧本的视觉化表达，包含场景描述、画面构图、镜头运动等 |
| VLM | 视觉语言模型，用于理解图像内容 |
| MCP | Model Context Protocol，模型上下文协议 |

## 2. 功能需求

### 需求 1: API 配置管理

**用户故事**: 作为用户，我希望在应用中配置模型供应商 API，以便使用 AI 功能。

**优先级**: P0 (必须实现)

#### 详细用例

**用例 1.1: 首次配置 API**

```
前置条件: 用户首次打开应用，未配置任何 API
触发条件: 用户打开应用

主流程:
1. 系统检测到无 API 配置，自动跳转到 API 配置页面
2. 系统显示支持的供应商列表（DeepSeek、OpenAI、通义千问、Gemini）
3. 用户选择供应商
4. 系统显示该供应商的输入字段（Base URL、API Key、模型列表）
5. 用户输入 API Key
6. 用户选择或输入模型名称
7. 用户点击"验证连接"
8. 系统发送测试请求验证 API Key
9. IF 验证成功:
   - 系统保存配置到 MMKV（加密）
   - 系统跳转到项目列表页
   - 系统显示"配置成功"提示
10. IF 验证失败:
    - 系统显示错误信息（如：401 Unauthorized）
    - 系统允许用户重试
    - 系统记录错误日志
```

**边界条件**:
- API Key 长度校验（最少 10 字符）
- Base URL 格式校验（必须是有效 URL）
- 网络超时时间：30 秒
- 验证失败后，配置不保存

**异常处理**:
- 网络不可用：显示"请检查网络连接"
- API 返回 401：显示"API Key 无效，请重新输入"
- API 返回 403：显示"API Key 权限不足"
- 超时：显示"连接超时，请重试"

#### 验收标准

| ID | 验收标准 | 优先级 |
|----|----------|--------|
| 1.1 | WHEN 用户首次打开应用，系统 SHALL 显示 API 配置引导页面 | P0 |
| 1.2 | WHEN 用户输入 API Key 和 Base URL，系统 SHALL 发送测试请求验证连接 | P0 |
| 1.3 | WHILE 用户已配置 API，系统 SHALL 允许修改配置参数 | P1 |
| 1.4 | IF API 验证失败，系统 SHALL 显示错误提示并允许重试 | P0 |
| 1.5 | 系统 SHALL 支持多种模型供应商配置（DeepSeek、OpenAI、通义千问、Gemini、自定义） | P0 |
| 1.6 | 系统 SHALL 提供预设模型列表供用户快速选择 | P1 |
| 1.7 | 系统 SHALL 支持自定义供应商（OpenAI 兼容协议） | P2 |

#### 数据模型

```kotlin
data class ApiConfig(
    val id: String = UUID.randomUUID().toString(),
    val provider: String,           // deepseek/openai/qwen/gemini/custom
    val apiKey: String,             // 加密存储
    val baseUrl: String,
    val defaultModel: String,
    val availableModels: List<String>,
    val createdAt: Long,
    val updatedAt: Long
)
```

### 需求 2: 聊天功能

**用户故事**: 作为用户，我希望与应用进行多轮对话，以便获得智能回复。

**优先级**: P0 (必须实现)

#### 详细用例

**用例 2.1: 发送消息**

```
前置条件: 用户已配置 API，已选择项目
触发条件: 用户在聊天界面输入消息并点击发送

主流程:
1. 系统将用户消息显示在聊天界面（右侧，蓝色气泡）
2. 系统显示加载动画（打字机效果）
3. 系统将消息发送到 Agent 状态机
4. Agent 状态机进入 COMPREHENDING 状态
5. Agent 调用文本生成 API（流式响应）
6. 系统实时显示 AI 回复（左侧，灰色气泡）
7. Agent 状态机进入 EXECUTING 状态（如有技能调用）
8. Agent 状态机进入 REFLECTING 状态
9. Agent 状态机进入 COMPLETED 状态
10. 系统将回复保存到数据库
11. 系统更新费用统计
12. 系统清空输入框
```

**用例 2.2: 多会话管理**

```
前置条件: 用户已创建多个会话
触发条件: 用户点击会话列表

主流程:
1. 系统显示会话列表（左侧抽屉）
2. 用户点击某个会话
3. 系统加载该会话的历史消息
4. 系统在聊天界面显示历史消息
5. 用户可以在该会话继续对话
6. 用户点击"新建会话"
7. 系统创建新会话
8. 系统跳转到新会话
```

**边界条件**:
- 单次对话最大 Token 数：8000（超出后自动压缩上下文）
- 消息最长长度：4000 字符
- 加载动画超时：30 秒

**异常处理**:
- 网络断开：显示"网络连接中断"，允许重试
- API 限流（429）：显示"请求过于频繁，请稍后重试"，自动等待后重试
- 内容过滤：显示"内容被过滤，请修改输入"

#### 验收标准

| ID | 验收标准 | 优先级 |
|----|----------|--------|
| 2.1 | WHEN 用户打开聊天界面，系统 SHALL 显示空白对话或上次会话记录 | P0 |
| 2.2 | WHEN 用户输入消息并发送，系统 SHALL 调用 API 获取回复 | P0 |
| 2.3 | WHILE AI 生成回复中，系统 SHALL 显示加载动画（打字机效果） | P0 |
| 2.4 | WHEN 回复完成后，系统 SHALL 显示完整回复内容 | P0 |
| 2.5 | WHILE 用户正在对话，系统 SHALL 保持上下文连贯性 | P0 |
| 2.6 | 系统 SHALL 支持用户手动清除对话历史 | P1 |
| 2.7 | IF 网络请求失败，系统 SHALL 显示错误提示并提供重试按钮 | P0 |
| 2.8 | 系统 SHALL 支持多会话切换 | P1 |
| 2.9 | 系统 SHALL 支持流式响应，实时显示生成内容 | P0 |

### 需求 3: 写小说功能

**用户故事**: 作为用户，我希望应用帮我创作小说内容，以便提高创作效率。

**优先级**: P0 (必须实现)

#### 详细用例

**用例 3.1: 创建新章节**

```
前置条件: 用户已选择小说项目
触发条件: 用户点击"新建章节"

主流程:
1. 系统显示新建章节对话框
2. 用户输入章节标题
3. 用户选择创建方式：
   - 空白创作：打开空编辑器
   - AI 续写：打开续写对话框
   - AI 生成：输入主题/大纲，AI 生成完整章节
4. IF 用户选择"AI 生成":
   - 用户输入主题、风格、字数要求
   - 系统调用 AI 生成章节内容
   - 系统显示生成进度
   - 生成完成后，系统打开编辑器
5. 用户在编辑器中编辑内容
6. 系统自动保存（每 30 秒）
7. 用户点击"保存"
8. 系统保存章节到数据库
9. 系统更新章节列表
```

**用例 3.2: 续写章节**

```
前置条件: 用户已打开章节编辑器
触发条件: 用户点击"续写"

主流程:
1. 系统获取当前章节内容和上下文
2. 系统显示续写输入框
3. 用户输入续写提示（可选）
4. 系统调用 AI 续写
5. 系统将续写内容插入到当前光标位置
6. 用户可以接受或撤销
```

**边界条件**:
- 章节最长字数：50000 字
- 自动保存间隔：30 秒
- 最大上下文长度：8000 Token

#### 验收标准

| ID | 验收标准 | 优先级 |
|----|----------|--------|
| 3.1 | WHEN 用户选择"写小说"模式，系统 SHALL 显示小说创作界面 | P0 |
| 3.2 | WHEN 用户输入小说主题或大纲，系统 SHALL 生成小说内容 | P0 |
| 3.3 | WHILE 生成中，系统 SHALL 实时显示生成进度 | P0 |
| 3.4 | WHEN 生成完成后，系统 SHALL 显示完整小说段落 | P0 |
| 3.5 | 系统 SHALL 允许用户继续续写或修改已有内容 | P0 |
| 3.6 | 系统 SHALL 支持保存小说内容到本地 | P0 |
| 3.7 | 系统 SHALL 提供小说章节管理功能（新建/编辑/删除/排序） | P0 |
| 3.8 | 系统 SHALL 支持自动保存（每 30 秒） | P1 |

## 4. 约束条件

### 4.1 技术约束

1. 必须使用 Kotlin 语言开发
2. UI 必须使用 Jetpack Compose
3. 架构必须采用 MVVM 模式
4. 必须使用 Hilt 进行依赖注入
5. 必须使用 Room Database 进行本地存储
6. 必须使用 OkHttp + Retrofit 进行网络请求
7. 必须支持多供应商抽象层

### 4.2 业务约束

1. 应用必须纯本地运行，无需自建后端服务
2. API Key 必须由用户提供，应用不得预置
3. 所有数据必须存储在本地，不得上传到第三方服务器
4. 必须支持离线模式（已缓存内容可离线访问）

### 4.3 法律约束

1. 必须遵守模型供应商的服务条款
2. 不得用于生成违法不良信息
3. 必须提供用户协议和隐私政策
