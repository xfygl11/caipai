## 一、项目概况

### 1.1 技术栈
- **语言**: TypeScript + Node.js
- **框架**: Express.js (后端) + Socket.io (实时通信)
- **AI SDK**: Vercel AI SDK (OpenAI compatible)
- **数据库**: SQLite (via Better-SQLite3)
- **打包**: Electron + electron-builder
- **技能系统**: Markdown-based Skill Registry

### 1.2 项目结构
```
Toonflow-app/
├── src/
│   ├── agents/           # AI Agent 系统
│   │   ├── scriptAgent/  # 剧本创作 Agent
│   │   └── productionAgent/  # 视频生产 Agent
│   ├── routes/           # API 路由 (18个模块)
│   ├── lib/              # 核心库
│   ├── utils/            # 工具函数
│   ├── types/            # TypeScript 类型定义
│   └── socket/           # WebSocket 实时通信
├── data/
│   ├── skills/           # 技能文件 (27个 .md 文件)
│   ├── vendor/           # AI 供应商配置
│   ├── models/           # 本地模型
│   └── db2.sqlite        # 数据库文件
└── build/                # 构建产物
```

## 二、UI功能模块详解

### 2.1 小说管理模块 (`/routes/novel`)

#### 功能列表
| 功能 | 路由 | 描述 |
|------|------|------|
| 获取小说列表 | `GET /api/novel` | 获取项目下所有小说章节 |
| 添加小说 | `POST /api/novel/add` | 导入/添加小说章节 |
| 更新小说 | `POST /api/novel/update` | 编辑小说内容 |
| 删除小说 | `POST /api/novel/del` | 删除小说章节 |
| 批量删除 | `POST /api/novel/batchDelete` | 批量删除小说 |

#### 事件提取 (`/routes/novel/event/generateEvents`)
**技能**: `event_extraction.md`
**流程**:
1. 调用 `u.cleanNovel(concurrentCount)` 清洗小说原文
2. 使用 `event_extraction` 技能提取关键事件
3. 输出 JSON 格式事件列表:
```json
{
  "eventId": "uuid",
  "chapterIndex": 1,
  "events": [
    {
      "eventIndex": 1,
      "description": "事件描述（50字以内）",
      "type": "conflict/introduction/development/climax/resolution",
      "characters": ["出场角色"],
      "location": "场景地点",
      "emotion": "主要情绪",
      "keyDialogue": "关键对白"
    }
  ]
}
```

#### 事件类型
- **introduction**: 介绍性事件，建立背景
- **conflict**: 冲突事件，推动剧情
- **development**: 发展事件，深化关系
- **climax**: 高潮事件，关键转折
- **resolution**: 解决事件，收束剧情

### 2.3 视频生产模块 (`/routes/production`)

#### 导演规划 (`production_execution_director_plan.md`)
**功能**: 基于剧本拆分场次并逐场分析
**输出**: `<scriptPlan>` XML 格式
**流程**:
1. 读取剧本数据 (`get_flowData("script")`)
2. 拆分场次 (同一时空下一段连续戏)
3. 统计台词数量和字数
4. 分析情绪浓度 (0-10) 和基调
5. 设计场间过渡 (动作衔接/空镜/淡入淡出)
6. 列出逐场注意事项

**输出结构**:
```xml
<scriptPlan>
  <!-- 分场汇总表 -->
  <scenes>
    <scene id="Sc1" name="地点·概况" lines="3" words="86" emotion="2" tone="独自等待·静默压抑"/>
  </scenes>
  
  <!-- 逐场注意事项 -->
  <notes>
    <scene id="Sc1">
      <emotionalPoint>关键情感砸点</emotionalPoint>
      <consistencyAnchor>一致性锚点</consistencyAnchor>
      <spatialDistance>空间距离</spatialDistance>
      <ambientSound>环境音</ambientSound>
      <errorTip>易错提示</errorTip>
    </scene>
  </notes>
  
  <!-- 场间过渡 -->
  <transitions>
    <transition from="Sc1" to="Sc2" type="动作衔接">角色起身推门往外走 → 接Sc2步入新场景</transition>
  </transitions>
</scriptPlan>
```

#### 分镜表 (`production_execution_storyboard_table.md`)
**功能**: 将剧本拆分成完整的分镜脚本
**核心铁律**:
1. 台词零删改 - 剧本中所有台词100%逐字搬运
2. 出场人物完整 - 每个角色都必须有视觉落点
3. 片段≤15秒 - 单片段台词超载时拆分
4. 长台词强制拆镜 - 超过20字必须拆分

**输出格式**:
```xml
<storyboardTable>
  <scene id="1" name="场景名">
    <characters>角色A, 角色B</characters>
    <fragment duration="10s">
      <assets>苏晚卿, 凌玄, 青云令, 大殿</assets>
      <assetIds>101, 100, 202, 300</assetIds>
      <shots>
        <shot index="1" duration="5" shotType="近景" camera="缓推">
          <description>画面描述</description>
          <dialogue>林刚暴怒说：『林志强，你到底打算吸我们的血到什么时候？』</dialogue>
          <sound>音效：手指划风声、急促呼吸声</sound>
        </shot>
      </shots>
    </fragment>
  </scene>
</storyboardTable>
```

## 三、Agent系统架构

### 3.1 剧本Agent (`/src/agents/scriptAgent`)

#### 子Agent结构
```
scriptAgent
├── decisionAgent (决策层)
│   └── skill: script_agent_decision.md
├── storySkeletonAgent (故事骨架)
│   └── skill: script_execution_skeleton.md
├── adaptationStrategyAgent (改编策略)
│   └── skill: script_execution_adaptation.md
├── scriptAgent (剧本生成)
│   └── skill: script_execution_script.md
└── supervisionAgent (监督层)
    └── skill: script_agent_supervision.md
```

#### 工作流程
1. **决策层** 接收用户输入
2. 调用 **故事骨架Agent** 构建故事结构
3. 调用 **改编策略Agent** 制定改编方案
4. 调用 **剧本Agent** 生成具体剧本
5. **监督Agent** 审核剧本质量

#### 子Agent结构
```
productionAgent
├── decisionAgent (决策层)
│   └── skill: production_agent_decision.md
├── deriveAssetsAgent (资产分析)
│   └── skill: production_execution_derive_assets.md
├── generateAssetsAgent (资产生成)
│   └── skill: production_execution_generate_assets.md
├── directorPlanAgent (导演规划)
│   └── skill: production_execution_director_plan.md
├── storyboardGenAgent (分镜生成)
│   └── skill: production_execution_storyboard_gen.md
├── storyboardPanelAgent (分镜面板)
│   └── skill: production_execution_storyboard_panel.md
└── storyboardTableAgent (分镜表)
    └── skill: production_execution_storyboard_table.md
```

#### 工作流程
1. **决策层** 分析项目需求
2. **资产分析Agent** 提取需要生成的资产
3. **资产生成Agent** 生成资产图片
4. **导演规划Agent** 拆分场次
5. **分镜表Agent** 生成完整分镜
6. **分镜面板Agent** 生成单个分镜图片

## 八、关键功能总结

### 8.1 时间提取
- **技能**: `event_extraction.md`
- **路由**: `POST /api/novel/event/generate`
- **工具**: `cleanNovel` 类
- **流程**: 清洗小说 → 提取事件 → 存储到数据库

### 8.2 视频骨架 (故事骨架)
- **技能**: `script_execution_skeleton.md`
- **Agent**: `storySkeletonAgent`
- **输出**: `<storySkeleton>` XML 格式
- **包含**: 故事核、人物小传、三幕结构、付费卡点、股价级反转

### 8.3 剧本创作
- **技能**: `script_execution_script.md`
- **Agent**: `scriptAgent`
- **输出**: `<scriptItem>` XML 格式
- **流程**: 接收骨架 → 改编策略 → 生成剧本

### 8.4 资产提取
- **技能**: 无专门技能，使用内置工具
- **路由**: `POST /api/script/extractAssets`
- **输出**: 新资产列表 + 已有资产引用

### 8.5 分镜生成
- **导演规划**: `production_execution_director_plan.md`
- **分镜表**: `production_execution_storyboard_table.md`
- **分镜面板**: `production_execution_storyboard_panel.md`

### 8.6 视频生成
- **技能**: `production_execution_generate_assets.md`
- **路由**: `POST /api/production/workbench/generateVideo`
- **流程**: 生成提示词 → 调用视频模型 → 轮询状态

## 九、技术亮点

1. **技能系统**: 基于Markdown的动态技能加载，支持热更新
2. **Agent架构**: 多层Agent协作，决策层-执行层-监督层分离
3. **流式输出**: 基于Socket.io的实时流式AI响应
4. **记忆系统**: RAG + 摘要 + 短期记忆三重记忆机制
5. **模型抽象**: 统一的AI接口，支持多供应商动态切换
